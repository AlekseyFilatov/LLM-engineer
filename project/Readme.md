# **Проект**
### Проектная работа

**Цель:**
В проектной работе вы закрепите и продемонстрируете полученные на курсе инженерные навыки путём разработки полноценного AI-сервиса, готового к интеграции в бизнес-процессы. Вы пройдете полный цикл LLM Driven Development: от подготовки данных и проектирования архитектуры (Advanced RAG, LangGraph) до оптимизации моделей (Fine-tuning, квантование) и развёртывания отказоустойчивой инфраструктуры с использованием современного LLMOps-стека (vLLM, Triton, Langfuse, Vector DBs). Итоговый проект станет сильным кейсом в вашем портфолио, подтверждающим квалификацию LLM-инженера.


**Описание/Пошаговая инструкция выполнения домашнего задания:**  
Выберите одну из предложенных ниже тем и выполните по ней проектное задание.

**Тема 3. Мультимодальный Omni-поисковик (VLM + Audio + Vector DB).**

Бизнес-смысл: Умный поиск по каталогу товаров (e-commerce) или медиа-архиву, где пользователь может искать картинки текстом, текст голосом или находить похожие изображения.  

 - Задача 1. (Мультимодальный индекс): Используйте модель CLIP для создания единого векторного пространства изображений и текстовых описаний. Загрузите эмбеддинги в ChromaDB или Qdrant.  
 - Задача 2. (Пайплайн): Напишите пайплайн обработки запросов. Если пользователь отправляет аудио - транскрибируйте его через Whisper. Если изображение - используйте VLM (например, Qwen-VL) для извлечения характеристик (теги, цвет, контекст), после чего делайте векторный поиск.  
 - Задача 3. (Деплой): Заверните сервис в Docker. Подключите Langfuse для мониторинга длительности транскрибации и генерации (latency metrics).  


**Формат сдачи:**  

 - Код: Решение должно храниться в публичном (или доступном проверяющим) репозитории GitHub/GitLab.
 - Воспроизводимость: Наличие Dockerfile / docker-compose.yml и файла зависимостей (requirements.txt / uv.lock).
 - Система должна запускаться одной командой.
 - Документация: Подробный README.md (Описание архитектуры, схема пайплайна, инструкция по запуску, примеры использования).
 - Демонстрация: Записанное скринкаст-видео (3-5 минут) с демонстрацией работы сервиса и разбором метрик в Langfuse/Grafana.

**Критерии оценки:**

 - Статус «Принято», если проект соответствует следующим критериям (must-have):

 - Функциональность: Решена заявленная бизнес-задача. Пайплайн (RAG/Агенты/FT) отрабатывает без критических ошибок и галлюцинаций.

 - Инженерная культура: Код структурирован (разбит на модули, используются классы/функции), отсутствуют захардкоженные API-ключи (используются .env).

 - Инфраструктура и LLMOps: Приложение завернуто в Docker. Реализован мониторинг (Langfuse) - в отчёте/видео видны трейсы запросов и замеры latency. Используется адекватный Serving (если модель локальная - vLLM/Triton/Ollama).

 - Оформление: Имеется исчерпывающий README.md с инструкцией по запуску. Предоставлены примеры входных данных (документы, тестовые запросы) для проверки.

 - Демонстрация: Проведена успешная защита проекта (или предоставлено понятное видео-демо работы системы).

**Будет плюсом:**
