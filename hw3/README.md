## Домашнее задание
### **Извлечение именованных сущностей (NER) с помощью LLM**

### Цель:
В этом ДЗ вы разработаете систему извлечения именованных сущностей (NER) с помощью API YandexGPT. В результате, вы получите пайплайн, способный автоматически вытаскивать из юридических документов реквизиты, даты, суммы и сроки, отдавая их в структурированном виде.


### Описание/Пошаговая инструкция выполнения домашнего задания:
#### 1. **Подготовка окружения и данных.**


- Получите ключи доступа к API YandexGPT (используйте каталог Yandex Cloud, сервисный аккаунт и API-ключ/IAM-токен согласно инструкции к уроку).
- Загрузите тестовый набор юридических документов (датасет на ваш выбор).
- Проведите базовую подготовку текстов: проверьте длину документов. Так как у LLM есть ограничение на размер контекстного окна, настройте обрезку слишком длинных текстов (truncation) или реализуйте простое разбиение на смысловые части (chunking).

#### 2. **Разработка системы промптов (Prompt Engineering).**

Опишите и настройте структуру запросов к YandexGPT:

- Системный промпт (System prompt): Задайте роль модели (например: «Ты - строгий и точный AI-помощник юриста. Твоя задача - извлекать факты из текста без искажений»).
Пользовательский промпт (User prompt): Четко перечислите целевые данные для извлечения:

- Реквизиты сторон (Названия компаний, ИНН, КПП).
Даты (дата подписания, сроки действия).
Суммы (с указанием валюты).
Сроки обязательств (в днях/месяцах или конкретных датах).

Примечание:

Вы можете выбрать другие именованные сущности, которые будете извлекать. Это может быть: ФИО, номер договора, адрес и тд.
Адаптируйте промпты под задачу, взяв за основу прописанные в задании примеры.

- Инструкция по формату (Formatting instructions): Жёстко укажите модели возвращать ответ только в формате валидного JSON-объекта, без сопроводительного текста. Предоставьте модели пример (Few-shot) желаемой структуры JSON.

#### 3. **Интеграция с API и парсинг результатов.**


- Настройте Python-скрипт (используя библиотеку requests или официальный SDK) для отправки текста документа и промпта в API YandexGPT.
- Настройте параметры генерации: установите низкую «температуру» (temperature ~ 0.1 - 0.3) для минимизации креативности и галлюцинаций.
- Напишите парсер ответа от LLM: извлеките строку с JSON из ответа (предусмотрите очистку от возможных Markdown-тегов, таких как json ...).
- Преобразуйте полученную строку в структурированный словарь Python (с помощью библиотеки json).

#### 4. **Анализ слабых мест и тестирование (Edge Cases).**

Прогоните через ваш пайплайн минимум 5–7 различных документов.
- Тест на отсутствие данных: Обязательно подайте на вход документ, в котором нет суммы или сроков (например, пустую доверенность или NDA). Проверьте, выдумает ли модель данные (галлюцинация) или корректно вернет null / None.
- Тест на зашумленный текст: Подайте документ с опечатками (имитация плохого OCR-распознавания скана).
- Определите узкие места: забывает ли модель закрывать скобки в JSON? Путает ли ИНН первой и второй стороны?

#### 5. **Отчёт и анализ.**


Соберите результаты в Jupyter Notebook (или Colab). Опишите, что настроено, и приведите примеры:

- Текст вашего итогового системного и пользовательского промпта.
- Примеры успешного извлечения: скриншоты или вывод ячеек в формате «Фрагмент исходного текста» -> «Полученный JSON».
- Примеры ошибок LLM (если были): где модель сгаллюцинировала или сломала структуру JSON, и ваши мысли, как это можно исправить.
- Сделайте вывод: насколько API YandexGPT готово к production-задачам по извлечению сущностей (NER) по сравнению с классическими ML-моделями (например, Natasha или Spacy), в чем плюсы и минусы LLM-подхода.
